# 규칙은 에이전트가 실제로 틀렸을 때 고친다

## 조항

에이전트 지시 파일의 규칙은 에이전트가 실제로 틀린 행동을 했을 때 고친다. 기능을 고칠 때마다 그 기능의 설명을 규칙으로 덧붙이지 않는다.

## 이유

에이전트의 실수를 고치려고 규칙을 수정한 뒤 준수율이 올랐다는 관찰이 있다 [9]. 기능 설명을 덧붙이는 습관은 원칙 P-001이 말하는 증가의 주된 경로다.

## 반대 근거와 판단

- **반대 근거**: [9]는 규칙 수정과 코드 수정이 동시에 일어나 인과를 분리하지 못했고, 준수 여부를 LLM이 채점했으며, 프로젝트 대부분이 소규모 1인 개발 TypeScript 웹이다.
  **판단**: 준수율 수치는 인용하지 않는다. 이 처방은 "덧붙이지 않는다"는 부분이 P-001에서, "틀렸을 때 고친다"는 부분이 [9]에서 온다. 뒤쪽 근거가 매우 약하므로 등급을 매우 낮음으로 둔다.

## 적용

- 기능을 고친 커밋에서 에이전트 지시 파일이 함께 바뀌면, 그 변경이 에이전트의 실제 실수에서 나왔는지 확인한다. 기능 설명이면 도구의 도움말이나 결정 기록으로 옮긴다.
- 규칙을 고칠 때는 이유 줄(R-001)에 계기가 된 실수를 한 줄로 적는다.

```markdown
- 커밋은 명시한 경로만 스테이징한다. (이유: 같은 작업 트리를 쓰는 다른 세션의 변경이 함께 커밋된 적이 있다)
```
